# Madeira 的 Steam Deck 风格首页

这份补丁基于 Madeira 0.2.0，把首页改为横向圆角封面、选中游戏展开、深灰蓝背景。点击后仍进入原游戏详情，Steam 下载、云存档和启动流程继续使用 Madeira 原来的实现。

同时保留之前实机使用的 VA-floor 修正：iOS 原生进程初始化时不再把已设置的地址下界重置到 64 KB。WoW 分支和其他平台的行为保持不变。这个修正已用实际初始化函数编译测试 48 种组合。

`source.json` 固定上游提交和构建标记。`patches/deck-home.patch` 包含界面、工程成员、版本标记和兼容修正，不包含游戏、个人存档、账号、配对信息和签名材料。

GitHub Actions 在 `codex/deck-ui-build` 分支构建，使用上游同款 `xcode-27` 标准环境，生成未用个人账号签名的完整 IPA。构建产物保留三天。产物生成后仍需检查资源和权限，再用原账号、原应用标识进行保留数据的原位安装。

预览通过不代表完整 app 已构建或已安装；以 Actions 结果和手机回读为准。首次构建需要编译 LLVM、FEX、Wine、DXMT 等依赖，可能需要数小时。

补丁修改的 Madeira 源码沿用 GPL-3.0-or-later 和 Madeira Converter Exception，详见本目录许可证。仓库其他独立脚本的许可不变。

## 11 月 18 日的 build 11

Hades 的启动闪退已经在手机上复现并修好。保留 build 9 的 `pipe2` 和 OpenGL 修正后，又发现重新编译的 Wine 会太早加载部分 Windows 系统 DLL。《港诡实录》和《行尸走肉》都在游戏窗口出现前退出。build 10 只换回 11 个模块，《港诡实录》还是会退。build 11 使用 Madeira 0.2.0 同一源码提交里的 32 个 ARM64EC 模块，保留原有的延迟加载关系，两款都能读取旧档进入场景。构建时也会检查几个关键 DLL 的依赖有没有又变成提前加载。

### 玩完以后核对的存档

收尾时切回 UU，再让 Madeira 联网检查了一遍。能在这台手机上匹配的云文件共 44 个：Hades 6 个、睡狗 9 个、冒牌富少 5 个、行尸走肉 15 个、武士零 Windows 版 9 个。没有待上传、待下载或需要选择的冲突。武士零另外 9 个 Mac 条目在这套 Windows 环境里没有对应路径。《港诡实录》返回 0 个云文件、0 条同步规则，实际读的是先前迁到手机上的本地存档。试玩写入的章节进度、自动存档和会话文件已单独备份；回到游戏库前逐项恢复了原进度。

### 这版怎么用

1. 原位更新 Madeira 时沿用之前的 Apple 账号和应用标识。第一次更新前，先备份游戏存档。如果 Steam Cloud 显示本地和云端有冲突，先核对两个存档的时间和进度。
2. 下载和核对云存档时，我用 UU 的 Steam 中国香港线路。开始玩之前先在游戏详情里打开 `Touch controls`。Hades 我保留了 1168×536、30 FPS，睡狗要在启动游戏前打开虚拟手柄。
3. 在手机已配对的 StikDebug 和 LocalDevVPN 上启用 Madeira 的 JIT。回到游戏库，闪电变蓝就启动游戏。我的手机需要 UU 才能登录 Steam，所以等 JIT 就绪、游戏开始启动后再切回 UU。两条 VPN 会互相替换。
4. 我从 Steam 原入口启动游戏，用「继续」进入现有进度。看到 `Loading Steam` 时先让它加载，这台手机有几次用了一分多钟。碰到新闪退，先看 Madeira 日志有没有启动对应的游戏 EXE，以及退出发生在创建窗口前还是读档后。

本机的续签包在 `dist/Madeira-0.2.0-deck-ui-wine-delayload-20261118-verified.ipa`。它以 build 9 的 Actions 产物为底包，换入与手机实测版相同的运行库，更新 32 个 DLL 的摘要后重新签了临时签名。核过全部 601 个运行库文件、依赖和签名。SHA-256 为 `39037eb838c7894a46e541fcddf026a15a60e1b387a1738a0c8874eceb3d792e`。仓库提供源码补丁和 Actions 工作流，这份临时签名包留在本机，安装时由 iloader 用自己的 Apple 开发签名重签。

## 早期 build 9 的 Hades 启动修正

build 7 在 iOS 26.5.1 上启动 Wine 时会调用系统缺少的 `pipe2`。build 8 改用兼容的管道接口后，Steam 已能启动 Hades.exe，但 32 位和 64 位 DirectX 版都会在创建窗口前退出。对照之前能玩的版本，构建脚本漏了上游的 `patches/wine-opengl-winios.patch`。

build 9 在编译 Wine 前应用这份补丁，同时重建手机端和 Windows 端组件。安装包检查覆盖了 `pipe2`、32 位和 ARM64EC OpenGL 的加载地址、运行库清单。完整包 SHA-256 为 `2216358baed5b1ab5721cf1026874566329e2be4a1d45b5eac9cd00a3e292966`。[build 9 构建记录](https://github.com/linxz-coder/iphone-steam-lab/actions/runs/44217309763)
